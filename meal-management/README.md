# 식수관리 태블릿 화면 (초기 UI)

이 폴더는 기존 메뉴 전광판과 분리된 식수관리 화면의 첫 단계입니다.

## 현재 포함된 기능

- Firestore의 `companies` 컬렉션에서 거래처를 읽습니다.
- 회사명 및 `aliases` 별칭으로 실시간 검색합니다.
- `favorite: true`인 거래처를 상단 즐겨찾기로 보여 줍니다.
- 거래처를 선택하면 해당 거래처에 관리자가 설정한 숫자 4자리 비밀번호를 입력합니다.
- 비밀번호는 관리자 페이지의 **거래처·비밀번호 관리**에서 거래처별로 설정·변경·해제합니다.
- 비밀번호 해시와 salt는 `companies` 문서의 `accessCodeHash`, `accessCodeSalt` 필드에 저장합니다. 평문 비밀번호는 저장하지 않습니다.
- 일치하면 STEP 3 식수 입력 초안 화면을 보여 줍니다.
- 총 인원/명단/혼합 입력 방식을 선택할 수 있고, 대표자 서명을 화면에 그릴 수 있습니다.
- 입력 내용 확인은 브라우저 안에서만 동작하며 현재 Firestore에는 저장하지 않습니다.
- 태블릿 크기에 맞춘 큰 버튼과 모바일 반응형 레이아웃을 제공합니다.

## 아직 연결하지 않은 기능

- 실제 저장되는 방문 그룹 식수 입력(숫자/명단/혼합)
- 대표자 서명 업로드 및 서버 저장
- 접수 번호 생성, 중복 제출 방지, 월말 마감
- 식수 데이터 관리자 승인 및 월말 마감

A안은 직원 편의를 위한 간편 잠금입니다. 비밀번호 해시를 브라우저에서 비교하므로 실제 접근 권한을 보호하는 인증 수단이 아닙니다. 4자리 숫자는 가능한 조합이 적어 해시를 통해 추측할 수 있습니다. 실제 운영 데이터 보호가 필요하면 Firebase Authentication과 제한적인 Firestore Security Rules, 서버 측 검증을 별도로 구성해야 합니다. 기존 `verifyCompanyCode` Cloud Function은 이 간편 잠금 흐름에서 호출하지 않습니다.

## Firestore 거래처 문서 예시

컬렉션: `companies`

문서 ID는 고유한 거래처 ID를 사용합니다.

```js
{
  name: "실제 거래처명",
  aliases: ["현장에서 부르는 약칭"],
  active: true,
  favorite: true,
  sortOrder: 10
}
```

위 값은 스키마 예시일 뿐 실제 거래처 데이터가 아닙니다. 실제 회사명은 관리자 확인 후 등록합니다.

## 테스트 및 배포 전 확인

1. 현재 저장소의 루트 `firestore.rules`는 2026년 8월 3일에 만료되는 테스트 규칙이므로 운영에 그대로 사용하지 않습니다.
2. 관리자 페이지의 비밀번호 설정/변경/해제와 식수 화면의 일치/불일치 동작을 테스트 거래처로 확인합니다.
3. 운영 전에 Firebase Authentication 및 Firestore Security Rules를 구성해 관리자만 거래처 비밀번호를 변경할 수 있도록 제한합니다.
4. 접수 저장 API, 서명 저장, 중복 제출 방지를 구현합니다.
5. 실제 거래처 데이터로 검색 별칭과 즐겨찾기를 검수합니다.
6. 두 대 이상의 태블릿에서 동시 접수 및 중복 제출 테스트를 진행합니다.

이 화면은 별도 URL `/meal-management/`에서 제공하도록 추가되었습니다. 기존 `/display/` 전광판 파일은 수정하지 않았습니다.
